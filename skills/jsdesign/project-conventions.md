# 目标项目约定（通用）

写页面前先侦察目标仓库：`AGENTS.md` / README / 邻近业务页与组件。**一切以目标项目既有习惯为准**；本文件仅在缺少约定时提供兜底建议。

## 目录与别名（先侦察再套用）

常见形态（按目标仓库实际路径调整，勿写死到本 skill）：

| 用途 | 常见路径 |
|------|----------|
| 业务页面 | `src/views/`、`src/pages/`、`app/` 等 |
| 静态资源 | `src/assets/`、`public/` 等 |
| 业务组件 | `src/components/` 或页面旁 `components/` |
| API / 请求层 | `src/api/`、`services/` 或项目既有封装 |
| 路径别名 | 以 `vite.config` / `tsconfig` 为准（常见 `@/`） |

## 静态资源落盘

```text
<项目内约定的资源目录>/<frame-slug>/
  icon-xxx.png
  card-bg-xxx.png
  bg-xxx.png
```

规则：

1. **`outputDir`** 必须是业务项目内**绝对路径**，禁止只落系统临时目录。
2. 文件名用**英文 kebab-case**，按用途命名（`icon-*`、`card-bg-*`、`bg-*`）。
3. **禁止**保留设计稿层名（如中文组名、`图层_*`、`路径_*`）；导出后立刻重命名。
4. 引用方式跟随目标项目（`import`、`public` URL、CSS `url` 等）；不要擅自换资源落点习惯。

## 页面文件拆分

复杂页可对齐邻近页习惯，例如：

```text
<页面目录>/
  index.*           # 模板 + 组装
  data.*            # mock / 配置型数据
  charts.*          # 图表 option 工厂（若项目有图表）
  types / type.*    # 类型（若项目有抽离习惯）
  components/       # 仅本页复用子块
```

简单页可单文件，但仍需把动态数值提成变量，禁止模板内写死业务数字。

## UI 与图表

1. **优先复用**目标项目已有基础组件、UI 库与样式体系；不要引入项目未使用的新 UI 栈。
2. 设计稿中的**数据图**（折线/柱状/面积/饼等）：
   - 使用项目既有图表封装（若有）+ 邻近页惯用 option / 配置写法；
   - 禁止擅自 `echarts.init` 另起一套，或用切图 PNG 冒充可交互图（除非用户只要静态示意）；
   - 序列与轴数据视为动态字段：放 mock / 工厂入参，禁止在配置里写死长业务数组。
3. 图例、单位、系列名、坐标刻度优先还原设计稿；主题与字体跟随项目图表封装。

## 编码约束

- 跟随目标项目的编码规范（`AGENTS.md`、lint、邻近页注释与类型习惯）。
- 数值 / 日期 / 工具：优先项目既有工具，不要新引无关依赖。
- 接口未定时：只留 mock、类型形状与加载入口注释；**不要**虚构不存在的 API 路径。
- 范围：只做用户要的那一屏/组件；挂路由、权限、API 模块等仅在用户要求时再做。

## 无约定时的兜底

```text
图片 → src/assets/images/<frame-slug>/ 或 public/design-assets/<frame-slug>/
页面 → 与邻近业务页同级
```

交付说明里写明选择理由。
